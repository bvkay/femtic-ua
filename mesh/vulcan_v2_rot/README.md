### Frame rotation (config `data.rotation`)

- data.rotation: magnetic -> grid, alpha 7.42 deg (explicit), all 120 stations; Z' = R(-alpha) Z R(-alpha)^T.
- Sensor frame: magnetic. Provenance: alpha = declination - grid convergence = 6.40 + 1.02 = 7.42 deg (magnetic north 7.42 deg clockwise of UTM 53S grid north): IGRF-14 declination via ppigrf, cross-checked to 1e-5 deg against an independent spherical-harmonic synthesis; convergence from pyproj. Per site at the acquisition epochs (2022.83, 2024.29, 2025.21) alpha is 7.362-7.488 deg, within 0.068 deg of 7.42. validation/rotation_2026-09-28/
- alpha is the azimuth of the sensor x axis clockwise from UTM grid north, the mesh x axis. Each EDI tensor, still in mV/km/nT, is rotated into the mesh frame before femticPy converts units, conjugates and applies the error floor: Z' = R(-alpha) Z R(-alpha)^T with R(t) = [[cos t, sin t], [-sin t, cos t]], and Var' = (M o M) Var with M = kron(R(-alpha), R(-alpha)) (the EDI components are taken as uncorrelated). The floor below uses the rotated |Z'xy| and |Z'yx|. Column rot_deg of station_map.csv holds each station's alpha. Checks C08 and C09 recompute the rotation from its explicit formulas; C15 and C16 test rotate_Z on synthetic tensors (validation/rotation_2026-09-28/README.md). C18 confirms that no EDI records a rotation of its own (ZROT 0, HX/HY azimuths 0/90, DECLINATION 0), so no tensor is rotated twice.

### Units, time convention, station layout

- Z is converted from the EDI unit mV/km/nT to ohm (V/A) by dividing by 10000/(4 pi) = 795.774715 (femticPy DataGen.convert_units); VAR is divided by the square of that factor.
- The EDIs use exp(+i omega t): at the selected bands the median EDI phase is 37.2 deg for Zxy (first quadrant) and -142.3 deg for Zyx (third quadrant). FEMTIC requires exp(-i omega t) (manual.txt:1015: response functions "in SI units with e-it time dependence"; the INV_MT_01 example has Zxy phase -45 deg). femticPy DataGen.conjugate therefore negates Im(Zxx), Im(Zxy), Im(Zyx) and Im(Zyy), i.e. observe.dat holds conj(Z_EDI) / (10000/(4 pi)), with Z_EDI first rotated as above. Check C10 confirms it on the written file: median phase Zxy -36.9 deg, Zyx 142.1 deg (Zyx taken in [0, 360)).
- OWNER_ELEMENT -1: each MT station line is `i  1000+i  0  x  y`. E comes from the element below the surface (owner type 0) and H from dummy VTF station 1000+i (owner type 1, the element above the surface, 0 frequencies) at the same x y (FEMTIC manual, "How to improve response functions at high frequencies"). inversion/control.dat carries `OWNER_ELEMENT -1`.
- x = north, y = east (km) from the origin in the Frame section; FEMTIC ignores station z and places each station on the mesh surface by (x, y). Coordinates are written to 1 m ('%.3f').

### Error floors

femticPy DataGen.apply_error_floor, config `data.error_floor_Z` = [0.2, 0.05, 0.05, 0.2] for [Zxx, Zxy, Zyx, Zyy]. For every site and frequency, with Z in ohm:

    floor_i = error_floor_Z[i] * sqrt(|Zxy| * |Zyx|)
    SE_i    = max( sqrt(VAR_i), floor_i )

SE_i is written as the standard error of both Re(Z_i) and Im(Z_i). The floor is therefore 5 % of the geometric mean of the off-diagonal magnitudes for Zxy and Zyx and 20 % of it for Zxx and Zyy (not of sqrt(Zxy^2 + Zyx^2), as the comment in the femticPy notebooks says). VAR_i is the EDI variance of the complex estimate. In these EDIs Geotools' own RHO.ERR equals 2 rho sqrt(VAR)/|Z| (ratio 1.0000 / 1.0000 / 1.0000 at the 1st / 50th / 99th percentile over 12996 off-diagonal values; 1518 further values have RHO or RHO.ERR EMPTY although Z is present, all at bands outside the selection unless listed under Design warnings), so sqrt(VAR_i) is the error Geotools attaches to |Z_i|; femticPy uses it unchanged for each part (a strict complex-Gaussian reading would give sqrt(VAR_i/2) per part, so the unfloored errors are conservative by up to sqrt(2)).

Fraction of (site, frequency) pairs where the floor replaced the EDI error: 100 %/97 %/96 %/100 %.
