- **D2 decided (Ben): sensors were aligned to geomagnetic north.** The EDIs carry DECLINATION 0 and
  ZROT 0, so Z is in the magnetic frame. prep currently rotates nothing and the mesh x axis is UTM 53
  grid north (convergence -1.02 deg at the site centre). Consequence: observe.dat must be regenerated
  with each tensor rotated from magnetic north to grid north by (declination - convergence), about
  +8 deg here, with errors propagated. Declination comes from IGRF/WMM at each site for the acquisition
  year (2022 grid; 2024/2025 infill; EDIs have no ACQDATE). The mesh and the half-space gate are
  unaffected (isotropic), so B4a can run with the current observe.dat; the 1-iteration memory test and
  the first inversion should use the rotated file. Work item C5 (data-rotation key in prep_vulcan.py,
  with a sign-convention test on a synthetic anisotropic tensor) is queued behind the running prep agent.
- **Rotation facts (Opus scout, evidence in validation/rotation_2026-09-28/):** FEMTIC cannot rotate data;
  femticPy's rotation only orients ellipsoids. Declination 6.40 E (IGRF-14, 2022.5-2025.5), convergence
  -1.017 deg, so magnetic north is **7.42 deg clockwise of grid north** (not ~8). Z_grid = R(-a) Z_mag R(-a)^T,
  variances via (M o M).Var. Sign verified on a synthetic 2D tensor (wrong sign gives 0.28 residual).
  Recommendation: one config value data.rotate_to_grid_deg = 7.42.
- **Acquisition dates (Ben):** 2022 grid Oct-Nov 2022; infill April 2024 and March 2025. Not in the EDIs
  (ACQDATE dummy). Recorded in validation/rotation_2026-09-28/README.md; C5 uses epochs 2022.83 / 2024.29 / 2025.21.
